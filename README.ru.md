# HangDoctor

[English version](README.md)

Диспетчер задач показывает, что процессор и память свободны, а компьютер всё равно на секунду замирает при переключении окон. HangDoctor 30 секунд наблюдает за системой, находит настоящую причину, объясняет её обычными словами и исправляет то, что можно исправить без перезагрузки.

Утилита выросла из разбора одного такого случая 14.11.2026. Программа зеркалирования телефона раз в секунду запускала `tasklist`. Из-за утечки хэндлов в ядре каждый вызов шёл 13 секунд, в WMI их копилось по два десятка, и Explorer подвисал, ожидая RPC. Диспетчер задач ничего необычного не показывал. Полный разбор того случая лежит в `ClaudeGeneral/pc/freezes`.

## Как запустить

Скачать `hangdoctor.exe` из [Releases](https://github.com/vasmarfas/hangdoctor/releases) и запустить двойным щелчком. Ставить ничего не нужно, работает на Windows 10 и 11 x64. Сборка пока не подписана, поэтому SmartScreen может переспросить.

Если стоит [uv](https://docs.astral.sh/uv/), можно запустить прямо из репозитория:

```
uvx --from git+https://github.com/vasmarfas/hangdoctor hangdoctor
```

Из исходников, из папки проекта: `uv run --no-project --with textual env PYTHONPATH=src python -m hangdoctor`.

В окне показывается вердикт: «Всё в порядке», «Есть что поправить» или «Компьютеру плохо». Под ним идут карточки проблем с объяснением, что делать, и кнопками исправлений. Цвет кнопки показывает риск: зелёная — безопасно, жёлтая — осторожно, красная — опасно. «Исправить всё, кроме опасного» запускает все зелёные и жёлтые исправления после одного подтверждения. Красные (перезагрузка, закрытие зависшей программы) запускаются только по одному, у каждого своё предупреждение. Исправления, которым нужны права администратора, помечены `*` и сами их запрашивают. Внизу вкладки с подробностями. `R` — проверить снова, `Q` — выйти. Язык берётся из Windows, переключается ключом `--lang en`.

Что проверяется и что исправляется, перечислено таблицами в английском README. Команды те же: `hangdoctor check`, `hangdoctor check --json`, `hangdoctor fix <код>`, `hangdoctor fix --all`, `hangdoctor fix --all --dangerous --yes`.

## Как устроено

Всё читается через родные API Windows, WMI по процессам не используется: он сам бывает причиной фризов. Наружу ничего не уходит, сети у утилиты нет.

| Путь | Что там |
| --- | --- |
| `src/hangdoctor/win.py` | ctypes-обёртки: процессы, хэндлы, теги пулов, время процессора (`NtQuerySystemInformation`), службы и загруженные драйверы (SCM), счётчики PDH, журналы через `wevtutil`, пинг таскбара, зависшие окна |
| `src/hangdoctor/probe.py` | замер: собирает всё за N секунд в объект `Sample` |
| `src/hangdoctor/checks.py` | правила: из `Sample` делают находки (`Finding`) с серьёзностью, текстом для человека, техническими деталями и исправлениями |
| `src/hangdoctor/fixes.py` | исправления с уровнем риска; если нужны права, запускают копию HangDoctor от администратора (`hangdoctor apply`) и забирают её результат |
| `src/hangdoctor/knowledge.py` | что известно заранее: теги пулов Windows, драйверы с известными утечками, оболочки и инструменты разработчика, системные процессы, рецепты перезапуска (Steam) |
| `src/hangdoctor/i18n.py` | все тексты на русском и английском |
| `src/hangdoctor/tui.py`, `report.py`, `cli.py` | окно на Textual, текстовый и JSON-отчёт, командная строка |
| `tests/` | тесты правил на подставных данных |
| `packaging/entry.py`, `.github/workflows/release.yml` | сборка `hangdoctor.exe` через PyInstaller; GitHub Actions собирает его на каждый push, а по тегу `v*` выкладывает в Releases |

Новая известная утечка добавляется строкой в `LEAKY_DRIVERS` в `knowledge.py`. Новая проверка — это функция в `checks.py`, тексты в обоих языках в `i18n.py` и тест в `tests/test_checks.py`.

## Выпуск версии

Поднять `version` в `pyproject.toml` и `__version__` в `src/hangdoctor/__init__.py`, закоммитить и поставить тег:

```
git tag v0.1.0
git push origin main --tags
```

Через несколько минут `hangdoctor.exe` появится в Releases.
